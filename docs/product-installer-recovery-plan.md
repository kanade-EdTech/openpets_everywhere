# 组合产品安装器与 ProductLauncher 恢复计划

状态：待实施  
故障基线：`OpenPets Everywhere 3.3.0-preview.2` Windows x64  
诊断日期：2026-07-23

## 目标

修复组合安装包安装后双击出现黑色控制台窗口并立即退出的问题，使
Everywhere 与 OpenPets 能从一个安装目录、一个 Launcher 和一个快捷方式
可靠启动。安装位置必须支持默认目录、其他盘符、空格和非 ASCII 字符。

本计划只处理组合产品的安装、启动、迁移、诊断和发行可靠性，不修改
`openpets-control/v1`、OpenPets 本地 IPC 或 Everywhere/OpenPets 的业务功能。

## 已确认的故障

本次真实安装位置为：

```text
D:\Games\OpenPets Everywhere
```

诊断结果：

- 桌面与开始菜单快捷方式正确指向安装目录内的
  `ProductLauncher.exe`。
- 安装根目录和 `versions\3.3.0-preview.2` 的产品清单、签名及组件文件均
  通过验证。
- `ProductLauncher.exe` 正常启动后返回退出码 `20`，标准错误为
  `pointer_invalid: Cannot read active product pointer`。
- 安装器生成的 `current.json` 将 `updatedAt` 写成 Windows PowerShell 5.1
  的旧式 `\/Date(...)\/` 格式；Launcher 的 JSON 解析器要求 ISO 8601，
  因而无法读取活动版本指针。
- 黑色窗口来自 Launcher 的控制台子系统；错误只写入标准错误，双击启动时
  控制台随进程退出，用户无法看到原因。

所以，自定义目录和路径中的空格不是根因。重新运行同一个安装包会再次生成
同样的错误指针，不能作为修复方法。

## 冻结的完成定义

只有同时满足以下条件，才能判定修复完成：

1. 新安装、覆盖安装和从 `3.3.0-preview.2` 升级均能生成或迁移有效的活动
   版本指针。
2. 用户双击快捷方式时不出现控制台黑框。
3. Launcher 启动失败时显示可理解的图形错误，并将稳定错误码和必要上下文
   写入本地日志。
4. Everywhere 和 OpenPets 从安装目录对应的同一冻结版本启动；开发目录中
   的进程不能让安装版静默失败。
5. 默认路径、其他盘符、包含空格的路径和包含中文的路径均通过真实安装验收。
6. 安装、升级或启动中断不得留下半写入的 `current.json` 或半激活版本。
7. 最终安装器、Launcher 和组件签名可验证，发布校验和与实际文件一致。

## 有序开发计划

### P1. 恢复源码并冻结产品状态契约

先恢复并纳入版本控制的 ProductLauncher、组合安装器和组合构建脚本。当前
工作树中的 `product/ProductLauncher/` 只有 `bin/`、`obj/` 等生成内容，
不能作为可维护源码。

冻结 `current.json` v1 契约：

- `schemaVersion`: 固定为 `1`。
- `activeVersion`: 非空版本标识，只能解析到安装根目录的 `versions/` 下。
- `previousVersion`: 可空，用于失败回滚。
- `updatedAt`: UTC ISO 8601 字符串。
- 未知字段可忽略；缺失、类型错误、路径逃逸和不可用版本必须返回稳定错误码。

同时明确源码、生成目录和密钥边界：

- 提交 Launcher、安装器、构建脚本和测试源码。
- 忽略 `.dotnet-cli-product/`、`bin/`、`obj/`、`product/build/`、
  `product/artifacts/` 和私钥。
- 公钥和非敏感发布元数据只有在构建契约需要时才进入版本控制。

阶段门槛：从干净检出能够构建 Launcher，且仓库中不存在依赖未跟踪二进制
才能继续开发。

### P2. 修复指针生成、读取和旧安装迁移

让安装器直接按冻结契约生成 JSON，禁止通过 Windows PowerShell 5.1 的
`ConvertTo-Json` 序列化日期。`updatedAt` 必须由明确的 UTC ISO 8601
格式化逻辑产生。

所有指针写入采用“同目录临时文件、刷新、原子替换”的方式。Launcher 在
激活版本前依次验证：

1. 指针结构；
2. 版本目录边界；
3. 版本清单签名；
4. 必需组件及哈希。

为已经安装的 `3.3.0-preview.2` 增加一次性迁移边界：只识别已知的
`\/Date(...)\/` 旧格式，将其转换并原子重写为 v1 ISO 8601 指针；正常运行
路径不继续产生或传播旧格式。迁移失败时保留原文件并给出明确诊断。

必须增加行为回归测试，分别证明：

- 安装器生成的指针可被 Launcher 直接读取；
- 旧式日期能被一次性迁移；
- 损坏 JSON、缺失版本、路径逃逸和被篡改清单会被拒绝；
- 写入中断不会破坏最后一个可用指针；
- `previousVersion` 可用于恢复最后一个已验证版本。

阶段门槛：未经手工修改文件，新安装和旧预览版升级都能通过
Launcher 的指针与产品校验。

### P3. 去除黑框并补齐可观察错误

将用户入口构建为 Windows GUI 子系统程序（`WinExe`），保留供自动化使用的
无交互诊断参数，例如 `--validate` 和 `--self-test`。

建立 Launcher 日志：

```text
%LOCALAPPDATA%\OpenPets Everywhere\logs\launcher.log
```

日志只记录版本、解析后的安全路径、阶段、错误码和子进程退出状态，不记录
密钥、令牌、提示词、截图或用户内容。启动失败时显示图形错误对话框，至少
包含：

- 稳定错误码；
- 简短中文/英文说明；
- 日志位置；
- “打开日志”和“复制诊断信息”操作。

对安装器、迁移和 Launcher 统一错误码，避免将解析异常直接暴露成不可操作的
堆栈信息。

阶段门槛：双击启动无控制台窗口；人为损坏指针时，用户能看到错误并能从日志
定位到同一个稳定错误码。

### P4. 加固启动、单实例和恢复流程

Launcher 必须区分组合产品实例、独立安装实例和开发构建实例，不能只根据
进程名判断成功。启动流程固定为：

1. 获取当前用户范围内的组合产品单实例锁；
2. 读取或迁移指针；
3. 验证活动版本；
4. 按冻结顺序启动 Everywhere 与 OpenPets；
5. 通过真实就绪信号确认两个组件可用；
6. 失败时停止本次新建的子进程，并尝试回滚到 `previousVersion`；
7. 记录最终状态并向用户显示可操作结果。

快捷方式必须只指向安装根目录中的 Launcher，且 Launcher 不依赖当前工作
目录。测试需覆盖已运行的开发版 Everywhere、已运行的独立 OpenPets、组件
崩溃、IPC 超时、被占用文件和升级中断。

阶段门槛：上述故障均不会静默退出、误报成功或启动混合版本。

### P5. 构建、签名与真实发行验收

新增单一的组合产品质量门：

```text
源码构建
→ 单元/契约测试
→ 生成安装器
→ 安装到干净目录
→ 运行 Launcher 自检
→ 启动两个组件
→ 故障与升级恢复测试
→ 签名、哈希和卸载验证
```

Windows x64 至少执行以下真实矩阵：

| 场景 | 路径或前置条件 | 预期 |
|---|---|---|
| 默认新安装 | `%LOCALAPPDATA%` 默认目录 | 一次启动成功 |
| 其他盘符 | `D:\Games\OpenPets Everywhere` | 一次启动成功 |
| 中文与空格 | 例如 `D:\应用\OpenPets Everywhere` | 一次启动成功 |
| 旧版升级 | 已安装 `3.3.0-preview.2` 错误指针 | 自动迁移并启动 |
| 覆盖安装 | 同版本或允许的后继版本 | 数据保留且指针有效 |
| 故障恢复 | 损坏活动版本、保留有效上一版本 | 回滚或明确失败 |
| 单实例 | 开发版/独立版已运行 | 不混用、不静默退出 |
| 卸载重装 | 保留或清理数据分别验证 | 行为符合用户选择 |

发行前还必须：

- 验证安装器、Launcher、Everywhere 和 OpenPets 的 Authenticode 状态；
- 验证产品清单签名和组件哈希；
- 从最终签名文件重新生成 SHA-256；
- 在全新 Windows 用户账户上从快捷方式启动，而不是从开发终端启动；
- 保存版本组合、测试结果、已知限制和最终哈希。

阶段门槛：矩阵全部通过后发布新的预览版本；不得覆盖或继续分发已知会生成
错误指针的 `3.3.0-preview.2` 安装器。

## 建议实施顺序

严格按 `P1 → P2 → P3 → P4 → P5` 执行。P2 是当前闪退的直接修复，P3
解决用户看不到错误的问题；但在 P1 恢复源码与可重复构建之前，不应直接修改
生成目录中的二进制，也不应把手工修正 `current.json` 当成正式修复。
